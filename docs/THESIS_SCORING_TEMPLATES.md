# Thesis 인과 그래프 점수 알고리즘

기존 유형별 템플릿과 고정 가중치 방식은 사용하지 않는다. Thesis를 만들거나
`raw_input`을 변경할 때 AI는 Thesis의 주장과 핵심 가정을 인과 그래프로 구조화한다.
점수 계산은 저장된 그래프와 아래 고정 규칙만 사용하며, Judge Agent는 계산 결과를
수정할 수 없다.

## 그래프 계약

- `CLAIM`: 중간 주장 또는 최종 주장이다. `AND`, `OR`, `CONTRIBUTING` 중 하나의
  연산자와 자식 노드를 가진다.
- `ASSUMPTION`: `key_assumptions`의 원문 하나와 정확히 연결되는 말단 노드다.
- 모든 핵심 가정은 정확히 한 번 등장해야 한다.
- 루트는 `CLAIM`이어야 하며 모든 노드는 루트에서 도달 가능해야 한다.
- 순환, 중복 ID, 누락된 가정, 알 수 없는 자식이 있으면 그래프 전체를 거부한다.

AI가 그래프를 생략하거나 유효하지 않은 그래프를 만들면 시스템은 모든 핵심 가정을
동일하게 `CONTRIBUTING`하는 단일 루트 그래프로 교체한다. 따라서 AI 출력 실패가 점수
계산 실패로 이어지지 않는다.

## 정보 × 가정 노드 행렬

모든 정보는 모든 `ASSUMPTION` 노드에 대해 하나의 판정 셀을 가진다. 따라서 정보가
M개이고 가정 노드가 N개이면 판정 셀은 M×N개다. 직접 다루지 않는 조합도
`NOT_ADDRESSED`, 강도 0으로 명시한다.

정보에 해당 노드 내용이 없다는 사실은 반박이 아니다. 반드시 `NOT_ADDRESSED`로 처리하며
기존 노드 상태와 전체 점수를 바꾸지 않는다. `SUPPORT` 또는 `CONTRADICT` 셀은 해당 노드를
직접 검증하는 원문 구간을 하나 이상 인용해야 한다. 노드별 원문 인용이 없으면 신뢰 코드가
판정을 `NOT_ADDRESSED`, 강도 0으로 강제 변환한다.

각 셀의 signed strength는 코드가 다음 고정식으로 계산한다.

| 영향도 | 강도 |
|---|---:|
| LOW | 0.09 |
| MEDIUM | 0.27 |
| HIGH | 0.54 |

```text
signed_strength = 방향(+1/-1/0) × 영향도 강도 × 노드 관련도(0~1)
```

같은 방향의 여러 정보는 단순 합산하지 않고 한계효과가 감소하도록 결합한다.

```text
combined_strength = 1 - ∏(1 - individual_strength)
assumption_state = combined_support - combined_contradict
```

같은 노드·방향에서 발행일이 7일 이내이고 내용 지문이 유사한 문서는 동일 사건으로 묶어
가장 강한 근거 한 건만 누적한다. 사건 식별값은 점수 상태에 저장되어 다음 분석의 재보도도
다시 누적되지 않는다.

상태는 -1~+1의 연속값이다. 중복 문서 ID는 다시 반영하지 않으며 새 방향성 근거가 없는
가정은 이전 상태를 유지한다.

## 그래프 전파와 점수

- `AND`: 자식 상태의 최솟값. 하나의 필수 조건이 깨지면 상위 주장이 제한된다.
- `OR`: 자식 상태의 최댓값. 대안 경로 중 하나가 유효하면 상위 주장을 지지할 수 있다.
- `CONTRIBUTING`: 자식 상태의 산술평균. 별도의 AI 가중치를 만들지 않는다.

```text
health_score = round_half_up(50 + 50 × root_state)
```

`root_state=-1`이면 0점, `0`이면 50점, `1`이면 100점이다. 근거 충족도는 루트 아래
말단 가정 중 실제 방향성 근거가 있는 가정의 비율로 별도 표시한다.

## 정보별 최종 점수 변화 귀속

AND/OR 그래프에서는 정보 하나의 효과가 다른 정보와 상호작용하므로 단순히 노드 강도에
50을 곱할 수 없다. 시스템은 정보를 그래프에 추가하는 여러 순서에서 각 정보의 한계
점수 변화를 계산하는 결정론적 Shapley 귀속을 사용한다. 정보가 7개 이하면 모든 순서를,
그보다 많으면 문서 ID에서 만든 고정 시드로 128개 순서를 사용한다. 따라서 같은 입력은
항상 같은 귀속값을 만들며 다음 관계를 만족한다.

```text
∑ information_score_delta = health_score - previous_score
```

프론트엔드는 `abs(information_score_delta)`가 큰 정보부터 정렬하며, 각 정보 아래에서
방향성이 있는 노드별 signed strength를 확인할 수 있다.

## BROKEN 판정

필수 가정은 루트에서 해당 가정까지 모든 경로가 `AND`일 때 코드가 자동으로 도출한다.
AI가 필수 여부를 직접 지정하지 않는다. 다음 조건을 모두 만족하면 Thesis는
`BROKEN`으로 고정된다.

1. 코드가 도출한 필수 가정이다.
2. 지지보다 강한 `HIGH` 반증이 있다.
3. 서로 다른 문서 ID의 반증이 두 번의 근거 반영에서 연속 확인된다.

같은 문서를 반복 처리해도 횟수는 증가하지 않는다. `BROKEN`은 이후 지지 근거가 생겨도
유지되며, 사용자가 `raw_input`을 변경해 논리를 재설정할 때만 새 그래프와 중립 점수
50으로 초기화된다.

## 저장 및 이전 데이터

새 Thesis에는 `logic_graph`와 `EVIDENCE_NODE_MATRIX_V2` 형식의 `score_breakdown`을 저장한다.
기존 템플릿 컬럼은 데이터베이스 마이그레이션 호환을 위해서만 남아 있으며 API와 점수
엔진에서는 사용하지 않는다. 기존 레코드에 그래프가 없으면 읽을 때 결정론적 폴백
그래프를 구성하고, 다음 논리 재설정부터 새 형식으로 저장한다.
