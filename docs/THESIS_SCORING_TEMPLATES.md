# Thesis 유형별 결정론적 점수 템플릿

## 목적

이 문서는 AI가 가중치와 핵심 가정을 매 분석마다 다시 판단하지 않도록 하는 기본
템플릿을 정의한다. AI는 사용자 Thesis를 가장 가까운 유형에 매핑한다. 생성 또는
`raw_input` 변경으로 논리가 재설정될 때 선택된 템플릿과 당시 카탈로그 스냅샷을 자동
저장한다. 정기 근거 분석에서는 템플릿을 다시 선택하지 않는다.

템플릿은 업종이 아니라 **가치가 만들어지는 인과 경로**를 기준으로 선택한다. 같은
반도체 기업이라도 고성장, 사이클 회복, 마진 개선 Thesis는 서로 다른 템플릿을 쓸 수
있다.

## 공통 운영 원칙

1. 한 Thesis에는 기본 템플릿 하나만 적용한다. 여러 유형이 섞이면 가장 중요한 가치
   창출 경로를 기본 유형으로 선택하고 나머지는 개별 가정 또는 위험으로 기록한다.
2. AI는 허용된 카탈로그에서 정확히 하나를 선택한다. 특수 유형이 명확하지 않으면
   `GENERAL_FUNDAMENTAL`을 선택한다.
3. 가중치는 10,000 basis points 정수로 저장하며 템플릿 내 합계는 항상 10,000이다.
4. `core` 슬롯의 동일 가정이 서로 다른 분석 회차에서 `CONTRADICT/HIGH`로 2회 연속
   확인되면 `BROKEN` hard gate를 활성화한다.
5. 근거가 없는 가정은 실패가 아니라 `UNKNOWN(0)`이다. 점수와 별도로 근거 충족도를
   표시한다.
6. 논리 재설정 시 새 템플릿 스냅샷으로 교체한다. 과거 분석 이력은 당시 스냅샷을 유지한다.
7. 같은 사건을 다룬 여러 문서는 한 사건으로 묶는다. 기사 수가 점수를 증가시키지 않는다.

## 템플릿 선택 규칙

다음 질문에서 가장 먼저 명확하게 `예`가 되는 유형을 후보로 삼는다.

1. 공식 승인, 임상 결과, 소송, 거래 종결 같은 사건 하나가 성패를 좌우하는가?
   → `CATALYST_EVENT`
2. 이미 악화된 회사가 내부 계획으로 정상화되는 것이 핵심인가?
   → `TURNAROUND`
3. 외부 재고·가격·수급 사이클의 변곡이 핵심인가?
   → `CYCLICAL_RECOVERY`
4. 비용, 믹스 또는 규모의 경제에 따른 마진 개선이 핵심인가?
   → `MARGIN_EXPANSION`
5. 고성장 시장의 채택과 단위경제성 개선이 핵심인가?
   → `SCALABLE_GROWTH`
6. 검증된 경쟁우위와 높은 재투자 수익률의 장기 지속이 핵심인가?
   → `QUALITY_COMPOUNDER`
7. 자산 또는 정상 이익의 할인 해소와 가치 실현 촉매가 핵심인가?
   → `ASSET_VALUE_RERATING`
8. 배당·분배의 지속 가능성이 핵심인가?
   → `INCOME_DISTRIBUTION`
9. 어느 하나도 명확하지 않은 균형형 Thesis인가?
   → `GENERAL_FUNDAMENTAL`

두 유형이 비슷하게 맞더라도 가중치를 섞어 새 템플릿을 즉석 생성하지 않는다. Thesis의
주된 가치 창출 경로에 가장 가까운 하나를 선택한다. 어느 것도 명확히 맞지 않으면
일반형을 쓰며, 새로운 반복 패턴이 확인되면 관리자가 카탈로그 버전에 추가한다.

## AI 선택과 자동 저장 계약 예시

```json
{
  "catalog_version": "1.0.0",
  "template_id": "SCALABLE_GROWTH",
  "template_catalog_version": "1.0.0",
  "template_snapshot": {
    "template_id": "SCALABLE_GROWTH",
    "catalog_version": "1.0.0",
    "assumption_slots": ["카탈로그의 전체 슬롯과 고정 가중치"]
  },
  "assumption_bindings": [
    {
      "slot_id": "market_demand",
      "assumptions": ["AI 인프라 지출이 계속 증가한다"]
    }
  ]
}
```

AI 출력 계약은 enum으로 제한하므로 카탈로그에 없는 ID는 저장할 수 없다. 템플릿 ID와
버전은 별도 컬럼에 저장하고, 가중치 전체는 JSON 스냅샷으로 함께 저장한다. 생성과
`raw_input` 수정은 이 과정을 실행하지만 정기 분석과 점수 갱신은 기존 스냅샷을 유지한다.

## 점수 계산과 상태 유지

AI는 `key_assumptions`의 원문을 바꾸지 않고 각 템플릿 슬롯에 최대 한 번 연결한다. 사용자가
언급하지 않은 슬롯은 빈 상태로 둔다. 점수 엔진은 MEDIUM/HIGH 방향성 근거를 다음 값으로
변환한다.

| 분류 | 강도 |
|---|---:|
| SUPPORT/HIGH | +1.0 |
| SUPPORT/MEDIUM | +0.5 |
| 방향성 근거 없음 | 0 |
| CONTRADICT/MEDIUM | -0.5 |
| CONTRADICT/HIGH | -1.0 |

한 가정에 지지와 반박이 함께 있으면 각 방향의 가장 강한 값만 선택해 상쇄한다. 동일 방향의
기사 수는 강도를 증가시키지 않는다. 새 방향성 근거가 발견된 가정만 상태를 교체하며, 근거가
없는 가정은 이전 분석 상태를 유지한다. 슬롯에 여러 가정이 연결되면 가정 상태의 평균을
사용한다.

```text
health_score = round(50 + 50 × Σ(weight_bps / 10,000 × assumption_state))
```

근거 충족도는 가중치를 반영해 실제 방향성 근거가 있는 가정 비율로 별도 계산한다.

### BROKEN 무효화 정책 v1.0.0

`BROKEN`은 낮은 점수만으로 부여하지 않고 다음 조건을 모두 만족할 때만 부여한다.

1. 해당 가정이 템플릿의 `core=true` 슬롯에 연결되어 있다.
2. 새 문서에서 `CONTRADICT/HIGH`로 분류되고 같은 회차의 SUPPORT 강도보다 강하다.
3. 위 조건이 서로 다른 문서를 사용한 2개 분석 회차에서 연속으로 확인된다.

같은 문서의 재수집이나 새 근거가 없는 회차는 연속 횟수를 늘리지 않는다. MEDIUM 반박,
비-Core 반박, 동률의 HIGH 지지·반박은 hard gate를 발동하지 않는다. 두 번째 확인으로
`BROKEN`이 되면 상태를 고정하며, 이후 지지 근거만으로 자동 복구하지 않는다. 사용자가
`raw_input`을 수정해 논리를 재설정해야 템플릿·점수·무효화 이력이 초기화된다.

## 설계 근거

- 성장 Thesis는 매출 성장만이 아니라 지속 가능한 마진과 성장에 필요한 재투자 효율을
  함께 봐야 한다. Aswath Damodaran의 성장기업 value driver 구분을 템플릿의 수요,
  수익성, 재투자 슬롯에 반영했다.
- SEC가 설명하는 MD&A의 주요 범위인 실적, 유동성, 자본 자원, 중요한 추세와 불확실성을
  모든 유형의 검증 질문과 위험 슬롯에 반영했다.
- 이는 기업가치 평가 모델이 아니라 사용자가 명시한 투자 논리의 상태를 일관되게 추적하기
  위한 점수표다. 따라서 시장가격 목표나 매수·매도 결론을 자동 생성하지 않는다.
